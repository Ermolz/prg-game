# Замітки доповідача (захист)

Короткі тези; деталі — у [REPORT.md](REPORT.md) і [SLIDES_OUTLINE.md](SLIDES_OUTLINE.md).

## Відкриття (30–60 с)

- Одна логіка Dots and Boxes: Prolog + Python, Java, C#.
- Prolog: ordsets, ядро, метрики, **greedy_safe** → **MiniMax** → **α–β**, CLI JSON-RPC для UI.

## Ядро Prolog (слайди 9–10)

- Глибина в **півходах**; 1 півхід = одне ребро; **extra turn** у стані після `apply_move/5`.
- На корені оновлюються α/β між варіантами ходу — менше `nodes`, є `cutoffs`.
- **Цифри з REPORT (узгодити зі слайдом):**
  - Порожня 2×2, глибина 3: повний MiniMax **1464** вузлів, **0** відсічень (**1464/0**); з α–β **286** вузлів, **25** відсічень (**286/25**); той самий хід.
  - Часткова 2×2, глибина 5: **18729** vs **449** вузлів; **163** відсічення; той самий хід.

## Живе демо (за запитом)

- `node ui-electron/scripts/demo-minimax-meta.mjs` або CLI: `strategy=minimax`, `depth=3`, `alphaBeta=true` → `nodes=286`, `cutoffs=25` (порожня 2×2 після init).
- Показати поля `meta`: `depthRequested`, `depthUsed`, `nodes`, `cutoffs`.

## Рефлексія (1–2 хв)

- **Навіщо Prolog для пошуку:** декларативне дерево, без ручного обходу стеку.
- **Складно:** детермінізм порядку, лічильники, JSON-RPC помилки, extra turn.
- **Без CLP:** дискретний стан, ordsets + арифметики достатньо; CLP не дав би виграшу при цій постановці.
- **Далі:** теорія ланцюгів, endgame на малих полях, сильніший бот.

## Усне пояснення (обов’язково спокійно сказати)

- **Чому greedy_safe — евристика:** вона оцінює лише **наступний** хід за локальними метриками (закриття, «третя сторона», ризик), без побудови дерева глибини; швидко, але не гарантує глобально найкращий хід на горизонті кількох півходів.
- **Чому MiniMax краще за «локальний» вибір:** він розглядає **ланцюг** відповідей суперника на задану глибину в півходах і мінімізує/максимізує оцінку з точки зору гравця кореня — це не одна локальна оцінка одного ходу, а **дерево** альтернатив.
- **Що робить Alpha-Beta:** те саме оптимальне рішення на глибині, що й повний MiniMax, але **відсікає** гілки, які не можуть покращити результат у корені; тому менше вузлів (`nodes`) і ненульові `cutoffs`.
- **Чому після замикання квадрата хід може лишитися тому самому гравцю:** правила гри; у стані після `apply_move/5` поле `Player` знову поточний, якщо хоча б одна клітинка закрита (**extra turn**).
- **Чому це важливо для дерева пошуку:** наступний рівень дерева відповідає **реальному** наступному ходу — тому самому гравцю або супернику; без цього max/min і глибина гублять сенс.

**Еталонні числа (порожня 2×2, depth 3):** MiniMax **1464/0**; MiniMax + α–β **286/25** — ті самі, що в [REPORT.md](REPORT.md) і на слайді з таблицею.
