## Власний внесок і переробка матеріалів

**Явно для звіту та ДистЕДУ:**

| Питання | Відповідь |
|--------|-----------|
| **Які зовнішні репозиторії використані?** | Лише з розділу «Порівняння з зовнішніми реалізаціями» нижче в цьому файлі (наприклад, `byvlstr/DotsAndBoxesProlog`, `hexanome/dots`, `FriedImage/dots-and-boxes`, `Polaris000/DotsNBoxesQLearning`, `sergiye/dots.and.boxes`, `markods/DotsAndBoxes`, `Armando8766/Dots-and-Boxes`, `aqeelanwar/Dots-and-Boxes`, `NiklasEi/dots-and-boxes-python` тощо). |
| **Навіщо вони?** | **Виключно comparative material** — огляд чужих архітектур і контраст із multi-engine CLI + Electron; **не** джерело готового коду проєкту. |
| **Чи було пряме копіювання коду?** | **Ні** — не копіювалися фрагменти з цих репозиторіїв у реалізацію ядра, бота, пошуку чи CLI. |
| **Ступінь переробки ідей** | Загальновідомі ідеї (правила гри, теорія MiniMax/α–β) адаптовані під модель стану цього проєкту; **переробка в робочий код — повна** (немає вставок «як у джерелі»). |
| **Власний внесок** | Орієнтовно **85–90%** коду і документації проєкту; **~10–15%** — загальна термінологія та ідеї без коду. |

**Підсумок:** зовнішні репозиторії з розділу «Порівняння» нижче використані **виключно як comparative material** (як інші підходи до UI та архітектури); **пряме копіювання коду** з них **не застосовувалось**. Теоретичні описи MiniMax / α–β і правил гри з Wikipedia дають лише загальновідому термінологію; **реалізація** ядра, метрик, пошуку, бота та CLI у цьому репозиторії — **авторська**. **Власний внесок** у код і документацію — орієнтовно **85–90%**; частка запозичених *ідей* без коду — **~10–15%**; **ступінь переробки** чужих ідей у робочий код проєкту — **100%** (немає фрагментів «як у джерелі»).

- **Зовнішні AI-репозиторії та чужі повні реалізації гри** використано лише як comparative material (огляд архітектури, контраст із multi-engine CLI); **прямого копіювання коду** не застосовувалось.
- **Теоретичні джерела** (Wikipedia, підручникові описи MiniMax / α–β): термінологія та ідеї алгоритмів адаптовані під модель стану цього проєкту; реалізація пошуку та ядра гри — **оригінальні**.
- **Орієнтовна оцінка:** власний внесок у проєктну логіку, код і документацію — **~85–90%**; частка ідей/структури, запозичених з описів правил і загальновідомих алгоритмів (без коду) — **~10–15%**; **ступінь переробки** запозичених *ідей* у коді проєкту — **100%** (немає фрагментів «як у джерелі»).
- **Інструменти ШІ:** використовувались для **чернеток текстів** (звіт, чеклисти, формулювання коментарів), **не** як джерело готового коду ядра гри; відповідність тестам і семантиці перевіряється вручну та через PlUnit/інтеграційні скрипти.

## Зовнішні джерела

1. **Dots and Boxes (rules)** — [Wikipedia: Dots and Boxes](https://en.wikipedia.org/wiki/Dots_and_Boxes) — правила гри, представлення поля та ходів.

2. **PSPACE-complete** — статті про складність комбінаторних ігор (опційно згадати для Dots and Boxes).

3. **SWI-Prolog library(ordsets)** — [ordsets](https://www.swi-prolog.org/pldoc/doc_for?object=section(%27A1%27,%27lib/ordsets.pl%27)) — впорядковані множини для зберігання ребер.

4. **SWI-Prolog findall/3** — документація вбудованого предикату для збору розв’язків.

5. **PlUnit** — [PlUnit](https://www.swi-prolog.org/pldoc/doc_for?object=section(%27A1%27,%27packages/plunit.html%27)) — unit-тестування в Prolog.

6. **pytest** — [pytest](https://docs.pytest.org/) — тестування Python.

7. **JUnit 5** — [JUnit 5 User Guide](https://junit.org/junit5/docs/current/user-guide/) — тестування Java.

8. **xUnit.net** — [xUnit.net](https://xunit.net/) — тестування .NET.

9. **Java HashSet / Set** — [Java Set](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/util/Set.html) — незмінність та копії множин.

10. **C# record struct** — [Microsoft Learn: record](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/builtin-types/record) — immutable value types.

11. **MiniMax / Alpha-Beta (теорія)** — підручники з теорії ігор та ШІ (мінімаксне дерево, відсічення α–β); наприклад огляд у [Wikipedia: Minimax](https://en.wikipedia.org/wiki/Minimax) та [Alpha–beta pruning](https://en.wikipedia.org/wiki/Alpha%E2%80%93beta_pruning). Ці джерела використані для узгодження термінології (глибина в півходах, граничні вузли); реалізація в репозиторії — оригінальна, без копіювання коду зовнішніх AI-репозиторіїв.

## Порівняння з зовнішніми реалізаціями (коротко)

> Зовнішні репозиторії з колонки «Порівняння» нижче використовувались як **comparative material** (архітектура, ідеї, контраст із multi-engine CLI), а не як джерело прямого переносу коду MiniMax чи UI.

> Цей розділ навмисно короткий: його мета — показати контраст підходів і підказати, що можна взяти для опису архітектури/доків. Посилання наведені як `owner/repo` на GitHub.

### Prolog

- **`byvlstr/DotsAndBoxesProlog`** (`https://github.com/byvlstr/DotsAndBoxesProlog`)
  - **Що реалізовано**: Prolog сервер (`server(5000)`) + web-клієнт (HTML/jQuery).
  - **Відмінність**: “Prolog backend + browser UI”, а не “multi-engine CLI + Electron UI + JSON-RPC”.
  - **Ідея для docs**: окремо пояснювати межу “логіка гри” vs “інтерфейс”, і як обрано транспорт/контракт.

- **`hexanome/dots`** (`https://github.com/hexanome/dots`)
  - **Що реалізовано**: компактна Prolog-реалізація з бітовим кодуванням сторін клітинки (1/2/4/8).
  - **Відмінність**: низькорівневе представлення стану клітинки замість вашого `state + edges + scores + player`.
  - **Ідея для docs**: у порівнянні чітко обґрунтувати вибір моделі (edges як множина) і як це спрощує контракт.

### Java

- **`FriedImage/dots-and-boxes`** (`https://github.com/FriedImage/dots-and-boxes`)
  - **Що реалізовано**: JavaFX desktop UI з власною моделлю (GameBoardBuilder/GameLogic/...).
  - **Відмінність**: Java тут — фронтенд; у вас Java — альтернативний рушій CLI.
  - **Ідея для docs**: приклад “UI-класифікації” сутностей (Line/Box/Owner) — корисно для пояснення renderer-компонентів.

- **`Polaris000/DotsNBoxesQLearning`** (`https://github.com/Polaris000/DotsNBoxesQLearning`)
  - **Що реалізовано**: акцент на Q-learning/агентах.
  - **Відмінність**: це “AI-centric” проєкт; у вас бот — узгоджена евристика для всіх рушіїв.
  - **Ідея для docs**: як приклад альтернативної мотивації проєкту (але без переносу AI в цей репозиторій).

### C#

- **`sergiye/dots.and.boxes`** (`https://github.com/sergiye/dots.and.boxes`)
  - **Що реалізовано**: самостійний C# desktop-проєкт.
  - **Відмінність**: у вас C# — CLI-рушій + ядро, що запускається Electron UI.
  - **Ідея для docs**: наголосити на “CLI як компонент” і на перевагах contract-driven інтеграції.

- **`markods/DotsAndBoxes`** (`https://github.com/markods/DotsAndBoxes`)
  - **Що реалізовано**: repo з тегами alpha-beta-pruning/game-ai.
  - **Відмінність**: сильний акцент на пошук/AI; у цьому репозиторії Prolog тепер також містить MiniMax/α–β, але з власною інтеграцією з ядром та JSON-RPC.
  - **Ідея для docs**: коротка ремарка про можливі альтернативи боту та порівняння з пошуком у Prolog.

### Python

- **`Armando8766/Dots-and-Boxes`** (`https://github.com/Armando8766/Dots-and-Boxes`)
  - **Що реалізовано**: Python-гра з AI (Minimax/Alpha-Beta) і параметрами (розмір, глибина).
  - **Відмінність**: “AI-centric”; у вас політика бота узгоджена між мовами і підпорядкована контракту.
  - **Ідея для docs**: приклад user-facing опису параметрів і запуску.

- **`aqeelanwar/Dots-and-Boxes`** (`https://github.com/aqeelanwar/Dots-and-Boxes`)
  - **Що реалізовано**: інтерактивна гра з user-facing README (правила кліків, результат).
  - **Відмінність**: значно простіша архітектура без multi-engine і JSON-RPC.
  - **Ідея для docs**: стиль “короткі правила + скріншоти/поведінка UI” (у вашому випадку — без зовнішніх ресурсів, але з чіткими пунктами).

- **`NiklasEi/dots-and-boxes-python`** (`https://github.com/NiklasEi/dots-and-boxes-python`)
  - **Що реалізовано**: базові правила + вибір розміру поля через аргументи.
  - **Відмінність**: single-language проєкт.
  - **Ідея для docs**: мінімалістичний опис запуску та правил (корисно як орієнтир для `docs/RULES_UA.md`).
