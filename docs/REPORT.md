# Звіт: Dots and Boxes — Prolog та імперативні реалізації

## Тема та виконавець

Проект: реалізація гри Dots and Boxes у декларативній (Prolog) та імперативній (Python, Java, C#) формах з порівнянням за критеріями. Виконавець: Yermolovych (транслит у іменах файлів: yermolovych).

## Аннотація

Реалізовано одну й ту ж логіку гри Dots and Boxes у чотирьох варіантах: ядро на SWI-Prolog (модулі utils, core, bot, main) та три імперативні порти — Python (пакет dab), Java (Gradle, record + HashSet), C# (.NET, record struct + HashSet). У всіх варіантах використано нормалізацію ребер, інкрементальну перевірку 0..2 сусідніх коробок та однакову політику бота (greedy_close, safe_no_third_side, fallback_min_risk). Порівняння виконано за критеріями: модель даних, контроль незмінності, стек тестування (PlUnit, pytest, JUnit5, xUnit). Тести узгоджені за сценаріями в усіх реалізаціях.

## Огляд існуючих рішень

Dots and Boxes — класична комбінаторна гра на графі сітки [1]. Підходи до реалізації: повний перебір ходів, евристичні боти, зведення до теорії ігор. Для навчальної мети обрано єдину формалізацію (point, edge, box, state) та порт на кілька мов без зміни логіки.

## Формалізація моделі

- **Точка:** point(X,Y), координати в межах 0..NX-1, 0..NY-1 (для точок сітки).
- **Ребро:** edge(P1,P2), нормалізоване (менша точка перша за терм-порівнянням); манхеттенська відстань між точками = 1.
- **Коробка:** box(X,Y) — верхній лівий кут квадрата 1×1.
- **Стан:** state(NX, NY, Edges, S1, S2, Player): розміри сітки, множина ребер, очки двох гравців, поточний гравець (1 або 2).

Кількість ребер на сітці: NX×(NY+1) + (NX+1)×NY.

## Prolog: ключові рішення

- **Ordsets** [3]: ребра зберігаються як впорядкований список без дублікатів; усі ребра нормалізовані через normalize_edge/2.
- **Інкрементальний підрахунок:** completed_boxes_by_edge перевіряє лише 0..2 коробки, інцидентних даному ребру (adjacent_box_for_edge, box_closed).
- **Без CLP(FD):** сітка мала, арифметика достатня; обґрунтування в DESIGN_NOTES.

## Імперативні реалізації

- **Python** — еталон: пакет dab (types, state, geometry, core, bot), frozen dataclass State, frozenset ребер. Мінімальний та зручний для тестів код.

- **Java** — той самий алгоритм: record для Point, Edge, State; HashSet для ребер; JUnit 5; збірка Gradle Groovy. Java варіант: HashSet + record.

- **C#** — той самий алгоритм: readonly record struct Point/Edge, sealed record State, HashSet<Edge>; xUnit. C# варіант: HashSet + record struct.

## Порівняння за критеріями

| Критерій              | Prolog      | Python    | Java           | C#                |
|-----------------------|------------|-----------|----------------|-------------------|
| Модель даних          | терми      | dataclass | record         | record struct     |
| Незмінність           | логична    | frozen    | immutable record | record struct   |
| Зберігання ребер      | ordset     | frozenset | HashSet        | HashSet           |
| Unit testing stack    | PlUnit     | pytest    | JUnit 5        | xUnit             |

Висновок: одна логіка дозволяє порівняти стилі (декларативний vs імперативний, типізація, тестування) при однакових сценаріях.

## Тестування

PlUnit (Prolog), pytest (Python), JUnit 5 (Java, Gradle), xUnit (C#). Сценарії: total_edges 2×2=12, possible_moves на порожній 2×2=12, повтор ребра нелегальний, закриття 1/2 box та extra turn, зміна гравця, game_over, детермінованість бота. Деталі — у TESTING.md.

## Висновки та рефлексія

Проект демонструє формалізацію однієї гри в одній логіці з чотирма реалізаціями. Складні місця: інкрементальна перевірка 0..2 box та узгодження політики бота між мовами. Трудоємкість: код (Prolog, Python, Java, C#) — орієнтовно X год; підготовка звіту та слайдів — Y год (заповнити за фактом). Застосування: навчальні проекти з логічного програмування та порівняння парадигм.
